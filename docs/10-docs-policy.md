# Ordo — Docs Policy

> Политика документации. Как создавать, обновлять, версионировать.
> Читается агентом при старте. Соблюдается строго.

---

## 1. Зачем это

Документация = **память проекта**. Без неё:
- Новый агент **не поймёт**.
- Ты **забудешь**.
- Проект превратится в **кашу**.

**Правило**: код без доков — **не мержится**.

## 3. Когда создавать документ

### ADR
- Новый модуль.
- Изменение архитектуры.
- Изменение стека.
- Новое внешнее решение (БД, хостинг, библиотека).
- Отступление от default.
- Изменение правил.

### RFC
- Новый модуль.
- Изменение границ модуля.
- Новый use-case.
- Новое событие.

### Task
- Новая фича.
- Новый модуль.
- Баг-фикс (если >1 файла).
- Рефакторинг.

### Обновление существующего
- Изменение БД → `04-data-model.md`.
- Изменение ролей → `03-rbac.md`.
- Изменение сущностей → `02-domain-model.md`.
- Изменение стека → `05-tech-stack.md`.
- Изменение цели → `00-vision.md`.

## 4. Правила обновления

### 4.1. Immutability
- **ADR не удаляются.**
- **ADR не редактируются** (кроме статуса).
- **RFC не удаляются.**
- **Task не удаляются.**
- Изменение = **новый документ**.

### 4.2. Статусы
- **Принято** — работает.
- **Предложено** — обсуждается.
- **Отклонено** — не принято.
- **Заменено** — отменено новым ADR. Ссылка на новый.
- **Выполнено** — Task завершён.
- **Отменено** — Task отменён.

### 4.3. Ссылки
- Каждый новый ADR **ссылается** на старый (если заменяет).
- Каждый RFC **ссылается** на ADR.
- Каждый Task **ссылается** на RFC.

### 4.4. Версионирование
- **Git** — версии.
- **Каждый коммит** — изменение.
- **Тег** — релиз.
- **История** — в git.

## 6. Definition of Done (для доков)

Задача **НЕ закрыта**, если:

- [ ] Код написан.
- [ ] Тесты проходят.
- [ ] Линт зелёный.
- [ ] Type check зелёный.
- [ ] **ADR обновлён** (если архитектура).
- [ ] **RFC обновлён** (если модуль).
- [ ] **Data model обновлён** (если БД).
- [ ] **RBAC обновлён** (если роли).
- [ ] **Vision обновлён** (если цель).
- [ ] **Task обновлён** (статус «Выполнено»).

**Если доки устарели** — задача **возвращается**.

## 7. Ревью документации

### Кто проверяет
- **Агент** — после каждой задачи.
- **Владелец** — перед мержем.
- **qa-reviewer** — в пайплайне.

### Что проверяет
- Доки **актуальны**.
- Доки **полные**.
- Доки **структурированы**.
- Доки **согласованы** (нет противоречий).

### Если устарели
- Задача **возвращается**.
- Агент **обновляет**.
- Только потом — **мерж**.
