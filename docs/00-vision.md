# Ordo — Vision

> **Ordo** — мультитенантная платформа управления учебным расписанием для медицинских колледжей.  
> **Компания**: YSF  
> **Домен**: ordo.app

---

## 1. Проблема

### 1.1. Для зама
- Составляет расписание **в Excel** неделями.
- Считает часы **вручную** (формулы в Excel).
- Следит за конфликтами **в голове**.
- **1070 человек** (70 преподавателей + 1000 студентов) зависят от **одного человека**.
- Если она заболеет — **университет встанет**.

### 1.2. Для студентов
- Не могут посмотреть расписание **офлайн**.
- Не могут **быстро найти** нужную пару.
- Не видят **изменений** в реальном времени.

### 1.3. Для преподавателей
- Не видят **свою нагрузку** в одном месте.
- Не могут **внести пожелания** централизованно.
- Узнают об изменениях **по звонку**.

### 1.4. Для других колледжей
- Нет **готового решения**.
- Каждый колледж делает **свой Excel**.
- Нет **стандарта**.

---

## 2. Решение

### 2.1. Для зама
- **Дашборд** — картина сверху на всё.
- **Редактор расписания** — drag-and-drop.
- **Проверка конфликтов** — автоматически.
- **Публикация** — в один клик.
- **Экспорт в Excel** — в любой момент.
- **Аудит** — кто что менял.

### 2.2. Для студентов
- **PWA** — работает офлайн.
- **Мгновенный доступ** — без логина.
- **Селектор групп** — все группы.
- **Поиск** — по группе, преподавателю, аудитории.
- **QR-код** — быстрый доступ.
- **Realtime** — изменения мгновенно.

### 2.3. Для преподавателей
- **Личный кабинет** — логин.
- **Свои пары** — в одном месте.
- **Своя нагрузка** — часы по дисциплинам.
- **Пожелания** — форма + статус.
- **Уведомления** — об изменениях.

### 2.4. Для других колледжей
- **Мультитенантность** — один колледж = один тенант.
- **Фича-флаги** — включение/отключение функций.
- **Онбординг** — за 1 день.

## 3. Пользователи

| Роль | Логин | Что делает |
|---|---|---|
| **Зам** (`schedule_owner`) | ✅ | Источник истины. Глаз сверху. |
| **Преподаватель** (`teacher`) | ✅ | Свои пары, нагрузка, пожелания. |
| **Студент** (`anon`) | ❌ | Смотрит расписание. |
| **Зав. отделением** (`department_head`) | ✅ | Своё отделение. |
| **Директор** (`tenant_admin`) | ✅ | Управляет колледжем. |
| **Основатель** (`owner`) | ✅ | Платформа, код, фичи. |

## 4. Метрики успеха

### 4.1. Для зама
- Время на составление расписания: **↓ в 5 раз**.
- Конфликты: **находит система**, не человек.
- Стресс: **↓**.

### 4.2. Для студентов
- Доступ: **мгновенно**, офлайн.
- Поиск: **< 3 секунд**.
- Обновления: **realtime**.

### 4.3. Для продукта
- Новый колледж: **1 день**.
- Новая фича: **1 спринт**.
- Багов: **< 1%**.

## 5. Что НЕ входит (Scope Boundaries)

- ❌ Оценки студентов.
- ❌ Посещаемость.
- ❌ Финансы.
- ❌ Интеграция с 1С (пока).
- ❌ Родительский доступ (пока).
- ❌ Мобильные приложения (только PWA).
- ❌ Видеоконференции.
- ❌ Электронный журнал.

**Детали**: `docs/06-scope-boundaries.md`.

---

## 6. Принципы

1. **Clean Architecture** — фичи добавляются без ломки.
2. **Мультитенантность** — с первого дня.
3. **Два PWA** — разделение ответственности.
4. **Один Supabase** — один источник истины.
5. **Анонимные студенты** — чистая БД.
6. **Bus factor ≥ 2** — зам не одна.
7. **Офлайн-first** — для студентов.
8. **Realtime** — для зама.
9. **Аудит** — всё логируется.
10. **Экспорт** — всегда доступен.

## 7. Дорожная карта (MVP)

### Спринт 0: Фундамент
- Монорепо, линтеры, тесты.
- Supabase-проект, миграции, RLS.
- `packages/domain` — каркас.
- ADR-журнал.

### Спринт 1: Identity + Academic Structure
- Пользователи, роли, тенанты.
- Специальности, группы, семестры.
- Импорт структуры из Excel.

### Спринт 2: Resources
- Преподаватели, аудитории, корпуса.
- Пожелания преподавателей.

### Спринт 3: Scheduling
- Рабочее место зама.
- Ручное составление + drag-and-drop.
- Проверка конфликтов.
- Версии, публикация, откат.
- Экспорт в Excel.

### Спринт 4: Publication
- PWA для студентов (офлайн).
- Личный кабинет преподавателя.
- Уведомления.

### Спринт 5: Analytics + Audit
- Нагрузка преподавателей.
- Отчёты.
- Журнал действий.

### Спринт 6: Solver (опционально)
- Автогенерация черновика.

### Спринт 7: Мультитенантность
- Изоляция данных.
- Онбординг нового колледжа.

**Итого MVP (без solver)**: ~3 месяца.
