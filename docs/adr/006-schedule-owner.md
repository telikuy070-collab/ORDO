# ADR-006: Schedule Owner — Глаз сверху

## Статус
Принято

## Контекст
Вisión документа (00-vision.md) роль `schedule_owner` (заместителя директора) описана как "Источник истины. Глаз сверху." Зам отвечает за составление расписания, контроль конфликтов, публикацию и экспорт. В Clean Architecture zam — это ключевой пользователь, который инициирует большинство workflows.

RBAC из 03-rbac.md определяет права `schedule_owner`:
- Всё в расписании
- Может создавать `schedule_owner`
- Может публиковать расписание
- Может экспортировать в Excel

## Решение
**Schedule Owner (schedule_owner)** имеет специальный статус в системе:

1. **Источник истины**: zam — единственный пользователь, который может создавать и изменять расписание в "сыром" виде (draft status)
2. **Глаз сверху**: интерфейс workspace PWA дает zam обзор всего колледжа, всех групп, преподавателей, аудиторий
3. **Уникальные права**:
   - Может переводить расписание из `draft` в `review` и `published`
   - Может откатывать версии (rollback)
   - Может импортировать структуру из Excel
   - Может экспортировать текущее расписание в Excel
   - Может создавать и управлять `teacher_preference`
   - Может создавать и управлять `constraints`
4. **RLS**: policies для `schedule_owner` роль имеют расширенные права по сравнению с `teacher` и `department_head`, но меньше, чем `owner` / `tenant_admin`
5. **Audit**: все действия зама логируются через AuditEvent (см. 02-domain-model.md, раздел 9)

## Обоснование
Special status для schedule_owner позволяет:
1. **Clear responsibility**: один человек несет ответственность за целостность расписания
2. **Controlled flow**: четкие переходы статуса (draft → review → published → archived)
3. **Audit trail**: все изменения traceable к конкретному пользователю (schedule_owner)
4. **AGENTS.md compliance**: "schedule_owner (зам) — Всё в расписании" (AGENTS.md, раздел 6)
5. **RBAC compliance**: "Только `owner` может создавать `tenant_admin`; только `tenant_admin` и выше могут создавать `schedule_owner`" (02-domain-model.md, инварианты)

## Последствия
- В интерфейсе workspace PWA zam видит дополнительные кнопки и меню, недоступные другим ролям
- RLS политики в Supabase различаются для `schedule_owner` по сравнению с другими role
- Все эндпоинты Edge Functions проверяют роль пользователя перед выполнением действий
- UI валидации запрещают другим пользователям выполнять действия schedule_owner
- Журнал аудита содержит все действия с расписанием с привязкой к schedule_owner

## Альтернативы
- **Equal rights for all roles**: дать всем пользователям доступ к редактированию расписания. Минусы: хаос в данных, конфликты, отсутствие ответственности.
- **Manager-only rights**: только `owner` может редактировать расписание. Минусы: bottleneck, zam не может оперативно вносить изменения, замедление работы.

**Выбранный вариант**: Special status for schedule_owner (рекомендовано 00-vision.md, 03-rbac.md, 01-architecture.md, AGENTS.md).
