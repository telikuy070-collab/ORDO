# ADR-002: Two PWA

## Статус
Принято

## Контекст
Ordo состоит из двух PWA-приложений, которые обслуживают разных пользователей с разными требованиями:

1. **apps/workspace** — PWA для персонала (зам, преподаватели, зав. отделением, директор)
   - Обязательный логин через Supabase Auth
   - Роли: `schedule_owner`, `teacher`, `department_head`, `tenant_admin`
   - Функции: дашборд, редактор расписания, аналитика, экспорт
   - Доступ к Realtime обновлениям

2. **apps/student** — PWA для студентов (анонимный доступ)
   - Без логина, анонимный просмотр
   - Роль: `anon`
   - Функции: просмотр расписания, поиск по группе/преподавателю/аудитории, QR-код, офлайн-режим
   - Realtime обновления через кэш

## Решение
Две отдельные приложения на базе React 19.3 + Vite 6:

- **workspace** подключен к Supabase с Auth (Service Role Key для миграций, anon key для операций)
- **student** работает без авторизации, использует анонимный доступ к Supabase
- Общая кодовая база через monorepo: `packages/*` (domain, application, infrastructure, ui, types, config)
- Разделение конфигурации Vite и Tailwind между приложениями
- Общие компоненты и типы выносятся в пакеты monorepo

## Обоснование
Два PWA позволяют:
1. **Безопасность**: workspace имеет полный доступ через Auth, student — только публичные данные
2. **Офлайн-first**: student PWA кэширует расписание для работы без интернета
3. **Простота**: отдельные цепочки деплоя на Vercel
4. **Чистая архитектура**: student не несет overhead авторизации, workspace — полные функции
5. **Мультитенантность**: один Supabase проект на оба приложения с RLS

## Последствия
- Два отдельных проекта на Vercel: `workspace.ordo.app` и `student.ordo.app`
- Общая конфигурация в monorepo, но сборка приложений независима
- Разные переменные окружения для workspace (VITE_SUPABASE_SERVICE_ROLE_KEY, и т.д.) и student (VITE_SUPABASE_ANON_KEY)
- Student PWA может работать полностью офлайн после первого загрузки
- Workspace PWA требует постоянного подключения для доступа к функциям

## Альтернативы
- **Едино приложение с флагами**: одно приложение с включением/отключением функций. Минусы: сложная логика условного рендеринга, больший пакет, проблемы с офлайн-режимом для студентов.
- **Отдельные репозитории**: два независимых репо. Минусы: дублирование кода monorepo, сложность синхронизации зависимостей, разные версии пакетов.

**Выбранный вариант**: Два PWA на базе одного monorepo (рекомендовано AGENTS.md, 00-vision.md, 01-architecture.md).
